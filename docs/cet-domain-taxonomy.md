> **生成物，别手改**：`python3 scripts/learn/gen_cet_domain_docs.py` 重生成。
> 唯一真相是 `src/test/resources/learn/cet-words-source/` 下的
> `cet-themes.tsv`（逐条归属）与 `cet-domain-tree.tsv`（域清单 + 顺序）。

## 一、两级结构：父域与细域

原来的 68 个语义域是**一层**。它有 35 个域装得太多 —— 最极端的「性质与特征」818 条，
从 `able` 到 `awkward` 什么形容词都有，一关 6 条随机抽出来彼此毫无关系，玩家记不住，
也没有「同类词一起记」的效果。

所以现在分两级：

| 层级 | 是什么 | 谁在用 |
|---|---|---|
| **父域**（68 个，原样保留） | 语义大类，只做分组与兜底依据 | 文档、碎域合并、`cet-domain-tree.tsv` 第一列 |
| **细域**（131 个，玩家看到的主题名） | 真正的关卡分类 | 关卡主题、前端显示 |

**粒度标准**：每个细域 **60~130 条**（约 10~22 关），**硬上限 150 条**（≈25 关）；
天然稀少的词类（感叹词、序数词）可以到 5 条，但**不许出现 1~2 条的细域**
（`MIN_PAIRS = 3` 以下的会被并走）。

**切分原则**：只按**词义所指的东西**分，不按词性、难度、词频；
**不跨父域**（一个词不会从「性质与特征」被挪到别的父域去）。
判据是那句自问：**把这个细域的词随机抽 6 个放进一关，玩家会不会觉得「这 6 个是一伙的」？**

## 五、维护手册

### 改某个词的归属

1. 改 `cet-themes.tsv` 第 3 列（保持 `英文\t释义\t细域` 三段式，英文释义一字不动）。
2. 若该域规模因此超过 150 条，就得再拆（见下）。

### 再细分某个域（粒度又不够时）

1. 把该域的词条切成 `gN-in.tsv`（`英文\t释义\t原域`）。
2. 逐条判到新细域，产出 `gN-out.tsv`（`英文\t释义\t细域`）与
   `gN-tree.tsv`（`父域\t细域\t说明`，说明 ≤ 30 字）。
3. 校验：`python3 scripts/learn/validate_cet_domains.py --parts <目录>`
   —— 它会检查「不增不删不改 / 不跨父域 / 细域已登记 / 与新老域名不撞 / 规模区间」。
4. 合并进 `cet-themes.tsv` 与 `cet-domain-tree.tsv`（未细分的域在树里占一行、父域 == 细域）。
5. **注意**：细域名会成为玩家看到的新主题名，**不要复用旧名字指代新含义**。

### 重建与同步（改完必做）

```bash
# 1) 重建词库
python3 scripts/learn/build_cet_words.py
# 2) 总校验（域体系 + 粒度 + 三副本）
python3 scripts/learn/validate_cet_domains.py
# 3) 同步小程序端（离线复刻接口载荷，不需要本机起服务）
python3 scripts/learn/dump_word_match_payload.py --out-dir /tmp/wm_payload
python3 scripts/learn/build_miniprogram_data.py \
    --from-files /tmp/wm_payload/data.json /tmp/wm_payload/cet.json
# 4) 重生成这两份文档
python3 scripts/learn/gen_cet_domain_docs.py
```

> ⚠️ **关数变了就必须升进度指纹版本** —— 网页版 `learn-word-match.html` 的
> `dataSignature()`、小程序 `utils/bank.js` 的 `signature()`，两处同步改。
> 只改归属、关数不变时也要改版本（「第 N 关」指向的内容变了，光看数字识别不出来）。

> ⚠️ **别顺手重跑词库生成链**：本项目的释义有人工修订，重跑会覆盖。
> 只重建四六级（`build_cet_words.py`）是安全的，它只读 `cet-themes.tsv` + 源清单。
