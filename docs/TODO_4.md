### 4. 情节拓展（Chapter Expansion）

#### 问题

当前章节写作生成的内容字数通常在 3000-5000 字左右，但部分章节可能需要更充实的内容（如 8000-10000 字）。目前没有机制支持在保留原有内容骨架的基础上进行**有控制的扩写**，用户只能重新生成或手动编辑。

#### 核心理念

> **扩写不是重写，而是在保持原有剧情骨架和节奏的前提下，对场景描写、对话细节、心理活动、环境氛围等进行有机填充和丰富。**

#### 设计方案

##### 4.1 功能定位

情节拓展是一个独立的操作步骤，位于章节写作完成之后、润色之前（或作为可选操作随时执行）。用户可以对任意已完成的章节执行扩展，将内容从当前字数扩充到目标字数。

##### 4.2 提示词模板

新增 `PromptSubStep`: `CHAPTER_EXPANSION`

模板变量：

| 变量 | 说明 |
|---|---|
| `{{chapterOutline}}` | 本章大纲（提供结构参考，确保扩写不偏离主线） |
| `{{chapterContent}}` | 章节原文（扩写的基础素材） |
| `{{creativeGuidance}}` | 创作指导（用户指定扩写方向，如"增加环境描写"、"丰富对话"、"补充心理活动"等） |
| `{{targetWordCount}}` | 目标字数（如 10000） |
| `{{currentWordCount}}` | 当前字数（如 5000） |

模板示意：
```yaml
sub_step: CHAPTER_EXPANSION
template: |
  请对以下章节内容进行情节拓展，将篇幅从约{{currentWordCount}}字扩充到约{{targetWordCount}}字。

  【本章大纲】
  {{chapterOutline}}

  【创作指导】
  {{creativeGuidance}}

  【扩写要求】
  1. 保持原有剧情走向和关键节点不变
  2. 不得删除或改写原文中的关键对话和重要情节
  3. 在合适位置自然插入：场景描写、角色心理、环境氛围、细节补充
  4. 扩写后的文本应当流畅自然，读者无法分辨哪些是原文哪些是新增
  5. 注意节奏控制，避免某一段过度膨胀导致比例失调

  【章节原文】
  {{chapterContent}}

  请输出扩展后的完整章节内容。
```

##### 4.3 内容保存与对比

扩展操作需要保存扩充前后的内容，支持用户对比查看和回退：

- `chapters.content`：存储当前生效的内容（扩展后覆盖此字段）
- `chapters.content_before_expansion`：新增字段，存储扩展前的原始内容（首次扩展时写入）
- `chapters.expansion_status`：新增字段，标记扩展状态：`NULL`（未扩展）/ `EXPANDED`（已扩展）

数据模型变更（迁移）：
```sql
ALTER TABLE chapters ADD COLUMN content_before_expansion TEXT;
ALTER TABLE chapters ADD COLUMN expansion_status VARCHAR(20);
```

##### 4.4 对比功能

前端提供**扩展前后对比**视图：
- 左右分栏或上下分栏显示原文与扩展版
- 支持一键回退到扩展前版本（将 `content_before_expansion` 恢复到 `content`）
- 支持重新扩展（基于原文再次执行扩展，覆盖当前扩展版本）

##### 4.5 操作入口

- 章节卡片上增加"情节拓展"按钮（仅在章节有内容时可用）
- 点击后弹出配置面板：
  - 目标字数输入（默认为当前字数 × 2，可自定义）
  - 创作指导输入框（可选，引导扩写方向）
  - 确认后执行扩展（SSE 流式输出）

##### 4.6 兼容性考虑

- 现有章节不受影响，`content_before_expansion` 和 `expansion_status` 默认为 NULL
- 润色步骤作用于当前 `content`（即扩展后的版本，如已扩展）
- 导出功能使用当前 `content`，无需特殊处理
- AutoRun 中可选择性启用情节拓展步骤（默认不启用，因为需要用户指定目标字数和创作指导）
